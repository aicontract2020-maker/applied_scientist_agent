# C4：跨任务数据资格审查（软件迭代）

本轮不运行研究实验，不等待 Delft 回复，也不修改任何已有实验的冻结证据。

问题：现有新任务的数据资格依赖专用文档，缺少统一、可离线交接的证据与审查状态。
实现一个纯标准库、仅处理显式提供的元数据文本的 `data-review` 入口：生成模板、冻结证据、只读检查、记录精确摘要上的人工决定。

固定八项不可省略的条件：来源/版本、用途许可、输入定义、目标定义、独立性与划分、质量有效性、留出暴露历史、标签访问边界。每项只允许 unresolved / supported / incompatible，并绑定理由和证据。缺失保持 BLOCKED；任一不兼容为数据资格 STOP；全部有证据才进入人工审查。接受只得到 QUALIFIED_FOR_PROTOCOL_DESIGN，永远不产生实验授权。

证据为用户显式选择的相对路径 UTF-8 文本，校验预先声明的 SHA-256，拒绝越界、符号链接、重复 JSON 键、未知字段和过大文件。冻结包携带证据内容用于离线审阅，默认私有权限、不覆盖；不是公开导出或自动脱敏工具。来源文字不作为代码、指令或链接执行。审查决定绑定完整包摘要，不能跨包复用。

软件验收：合成证据覆盖未决/不兼容/待审/接受/拒绝；被改动证据或决定必须拒绝；未决项不能接受；CLI 的检查不改动包、不预留数据、不调用网络、模型或 runner。回归测试保护既有协议。所有模拟结论明确为软件验证，不证明真实数据资格、许可效力或科学收益。

边界：不自动认证证据真实性、审查者身份或研究独立性；不替代许可判断、任务专用适配、预注册、隔离执行及停止记忆。旧 runner 不自动读取新包，历史证据不迁移。后续接入新数据 adapter 需明确新协议和单独执行审查。交付工程审查说明后停在用户验收点。
