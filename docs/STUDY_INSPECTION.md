# 运行状态与只读审计

0.13.0 提供不调用模型、不读图评分、不改原始产物的研究检查命令。所有输出为JSON；原始证据不会因审计而被重新写入，导出可由调用者重定向到新文件。

```sh
python3 -m research_harness study list
python3 -m research_harness study status --run runs/my-study
python3 -m research_harness study audit --run runs/my-study
```

`study list --root /path/to/checkout` 查看另一个源码副本的本地自主运行与预留。导入的其他机器研究摘要仍由 `memory status` 展示；旧的可信脚本 `protocol.json` 工作区不混入自主研究列表。

## 进度与存活是两回事

status 显示已记录的阶段、最后事件、声明的结果、是否存在AGENT_FINISHED及读取错误。没有终局结果时，按账本显示准备、文献阅读、干预审查、已注册或实验已开始。只有任务目录但没有运行目录的研究显示RESERVED。

`liveness` 始终为UNKNOWN。相同的最后事件可能来自仍在运行的研究，也可能来自进程崩溃或主机重启；不能用文件时间或旧PID猜测它是否还活着。缺失或尾部不完整的JSON行会明确报告。命令不恢复任务、不申请新实验、不修改STOP、不释放留出图。排查后保留原证据，任何新研究仍按原有新假设/注册规则进行。

## 审计做什么

- 核对注册、审查、实验、决定和agent退出的次数与顺序，拒绝先运行后注册、拒绝后仍运行及重复机会。
- 核对冻结候选、最终候选、方案/策略字段，以及REGISTER/EXPERIMENT_STARTED的协议哈希；新门槛启用时还要求审查PASS及其代码/方案绑定和对应账本。
- 核对result与决定事件一致、报告存在并包含相同状态，以及已记录的原始文献阅读和原生检索证据。
- 对有效测量，检查逐图身份、重复/遗漏、有限分数和正延迟，核对均值，再使用原冻结bootstrap种子/次数/置信度重新计算效应、变异、区间和延迟比。最后独立核对所有采用门槛与STOP/CONTINUE决定。
- 对测量无效的STOP与注册前REJECTED，验证相应终止路径，保持INVALID、NOT_RUN与有效科学决定的区别。符合记录规则的失败可以通过完整性审计。
- 若文件缺失、损坏、为符号链接、超过读取限制或在读取期间变化，返回审计失败；不会把部分结果冒充完成。JSON/账本文件限4 MiB；统计重算最多100张、100,000次重采样且乘积不超过1,000,000。超出当前受支持SR协议工作量会明确拒绝，绝不偷偷减少重复次数。

`study audit` 的退出0只表示本次检查建立了产物一致性，**不是科研成功**。退出1表示缺失、不一致、读取不稳定或协议不受支持。status/list只描述进度，不能替代审计。正常运行中的研究可能因为产物尚未完成而审计失败；此时不应自动重跑研究。

## 新研究的完成检查

`research --id` 完成后现在强制调用同一套只读审计，将结果放入 `workflow.json` 的 `completion_audit`。审计失败会阻止 `workflow_completed=true`，并以非零退出结束；不会自动修复数据、改方案、重新评分或运行第二次实验。历史文件不被批量回填；保留旧接口默认行为以读取过去的记录。

## 边界与验收

审计重算的是已经保存的逐图数值，不是重新运行模型/评价器。它不验证图像像素、权重、所有历史输入是否仍在当前机器上，不执行候选源码，不重新读取论文，不认证发送者，也不证明干预新颖性或科学解释正确。例如G6数值账本可以一致，空提案问题仍需保留既有操作者审阅和PROPOSAL_FAILURE研究记忆；不能凭audit_ok为其背书。

当前输入格式是原始 `runs/ID/` 完整运行目录；Git中的精选公开evidence目录可能缺少原始文件，不能假装是完整运行。并发写入检查只能发现观察窗口内的元数据变化，不是分布式一致快照或防恶意篡改的签名。

本轮98项完整依赖软件测试通过；纯Python相同98项通过、跳过4项科学依赖用例。新增测试用合成分数覆盖篡改、重复图像、缺失/损坏、拒绝/无效路径、变化快照与严格完成检查。另对本机保留的G7完整原始镜像离线审计，29项检查通过，重算均值为−0.0822601914 dB；审计前后73个产物文件的内容哈希全部未变。没有新增模型调用、图像评分、科研实验或重试。
