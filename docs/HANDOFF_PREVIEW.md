# 交接导入前预览（C11）

0.29 在不写入本地约束的情况下检查统一交接包与当前 checkout 能否合并，并
显示会增加/更新的记录。格式保持 v3，继续读取 v1/v2；无需迁移旧包。

```sh
python3 -m research_harness handoff --root /path/to/receiver preview /private/state-v3.json
# 审阅输出后，将其中的 preview_sha256 原样用于导入
python3 -m research_harness handoff --root /path/to/receiver import /private/state-v3.json --expect-preview SHA_FROM_PREVIEW
```

旧 `tabular handoff` 别名提供相同功能。`verify` 仍只校验外部包的格式和摘要，
不检查本地合并；`preview` 同时读取当前回归、数据暂停、Airfoil 和提案记录。
预览不会创建 checkout、锁文件、记忆、研究目录或批准，只向标准输出显示结果。

## 阅读预览

- `incoming` / `current` / `merged_state`：来包、当前和合并后的组件计数与摘要。
- `changes`：各组件的前后数量，以及新增、更新记录的身份；这些是记录身份，
  不是原始数据。数量不变时也显示终局或绑定补全，不能把相同计数当成没有变化。
- `missing_components`：旧包没带的组件。缺项不等于发送方无历史；导入不删除
  接收方已有记录。所有版本都不能证明未提供的历史不存在。
- `newly_imported_proposal_scopes`：将首次受到“导入提案占用”限制的作用域。
  `local_recovery_blocked_scopes` 是其中同时有本地预留的部分：导入后，即使
  记录总数/摘要不变，也不能按原本机启动故障恢复入口尝试。
- 上述恢复范围只披露限制，**不认定本机有资格恢复**；预览不读取模型输出、
  失败日志或恢复证据，不放宽原来零事件、无提案、单次本机恢复的条件。

冲突、损坏和超出原合并限额均报错；预览和导入使用同一套四组件合并函数。
没有部分成功的合并结果或“忽略冲突”选项，仍由操作者核对已有证据。

## 按预览导入

`--expect-preview` 是可选的本地状态前置条件。导入在原 checkout 锁内重新
计算预览，完全匹配后才一次发布。摘要绑定来包内容、解析后的接收目录路径、
当前约束、已有统一包身份、本地提案作用域和预计结果；它不是研究执行批准。

更换来包、接收路径、新增暂停/占用/终局，或改变导入来源，即使总数
不变，也会使旧预览失效。目录符号链接别名若解析到同一 checkout 可共用预览。
修改 JSON 空白但内容一致不改变包摘要。每个接收方应针对自己的状态预览；
摘要不绑定机器身份，不同机器若路径和全部所读约束一致，可能得到同一摘要。

收到 `Handoff preview changed` 后，应重新预览并核对变化；不要为了通过而
删除记录、换空包或取消检查。一次成功导入也会改变已存包身份，所以用旧摘要
重复导入会拒绝。重新预览后再导入返回 `ALREADY_IMPORTED`，不重复新增记录。
未提供该参数的旧导入仍兼容，并保留原校验、锁、原子性和重复幂等行为。

预览不持锁，只是时点观察；最终导入以锁内重查为准。被拒绝的实际 import
可能创建原有 `.cache/research-state.lock`，但不会发布交接包、修改研究约束
或启动任何研究。锁只协调遵守同一 checkout 协议的进程，不是跨机器实时锁，
也不防御恶意进程绕过文件协议。这里的摘要检查不是签名、身份认证或权限系统。

保持 SR 记忆、完整私有证据独立，既有 STOP、占用、暂停、数据资格、预注册、
人工执行批准和隔离边界均不变。此功能不会开启研究模型、训练、评分或恢复。
