# SR 已准备任务的启动前检查

0.32.0 为正式 SR 启动命令增加当前约束检查。准备完成并不保证之后仍能启动：
若后来导入了新的停止路线、文献或数据占用，旧准备不会自动沿用过期状态。

只读检查无需模型服务或科学依赖（Python >=3.10）：

```sh
python3 -m research_harness sr-preflight --study /checkout/local_studies/ID
```

`READY_FOR_LAUNCH_CHECKS` 仅表示冻结材料与当前 SR 约束一致，
`execution_authorized` 始终为 false。它不检查安装、登录或内核隔离，不运行
模型、不注册实验，也不创建目录、锁、批准或新的预留。命令会读取冻结文件
计算摘要，包括所选图像的原始字节；不会解析图像或计算科学指标。

## 正式启动路径

`research ID` 仍先运行原 doctor，再准备新的任务并启动；不能重新使用旧 ID。
对于已经准备好的任务，正式启动命令为：

```sh
.venv-sr/bin/python -m research_harness autonomous \
  --study /checkout/local_studies/ID --out /checkout/runs/ID --literature
```

这是使用方法，**不是本轮批准执行实验的指令**。实际运行仍须遵守已有研究
范围和批准；预注册、单次实验及 STOP 判定不变。

`autonomous`、`research` 和直接 `python -m research_harness.autonomy`
模块入口共用检查。直接模块入口现在也必须传 `--study`，不再回退到历史 G2。
输出固定在当前安装所对应 checkout 的 `runs/ID`；换 `--out` 不能绕过一次
执行限制。独立启动在原 checkout 锁内完成检查→doctor→复查→整个控制器
周期，合作进程无法在期间导入记忆或另开研究。

## 会拒绝什么

- 历史任务、证据副本、其他目录、改名任务或不同 checkout 的准备材料。
  新准备的 input lock 会记录 checkout 路径；缺少该来源字段的旧准备也拒绝。
- 已存在运行目录，包括空目录或未完成尝试；不覆盖、不自动重试。
- 缺少必需冻结文件、源码增删/修改、链接或非普通文件、路径越界、图像/政策
  字节变化及选择记录不一致。固定任务单个冻结文件读取上限 256 MiB。
- 自身预留已经终结、绑定变化，或其图像被标记为已评分。
- 扣除自身精确未执行预留后，当前 SR 约束与准备时不同。新增另一项 SR 预留
  即使图像不重叠，也保守地使较早准备失效；不会自动补充文献、路线或改选图像。
- doctor 失败或其间状态变化。拒绝发生在创建运行目录和调用研究模型之前。

被拒绝的准备和占用继续保留。核对变化与已有记录后，若确需新协议须另行审查；
不要删除占用、改写摘要、复制目录或换名字来救回失效路线。导入旧/空交接包
不能恢复旧状态。失败提示不是新的科学 STOP，也不是释放留出的许可。

## 保持的边界

只读 preflight 是时点观察，正式启动会重新检查。新增的是支持的命令入口及
统一研究入口的保护；`AutonomousStudy` / `LiteratureStudy` 低层 Python
控制器仍用于受信任代码和隔离软件探针，不是对任意本地 Python 调用的权限系统。
路径与摘要是完整性声明，不是签名，也不防御有权限直接篡改整个本地状态的人。

历史只读审计和证据交接保留。科学门槛、研究控制器内部预注册/运行/评价逻辑、
原隔离实现不变。没有引入 SR 新数据资格适配、跨机器实时协调、自动恢复或新研究。
