# 回归约束状态的一次性交接（C8）

0.26 新增 `tabular handoff`，将**回归停止／已用数据记录 + 当前全部数据暂停**
放进一个固定格式包。接收方一次导入两类约束，减少分别导入时遗漏暂停的机会。
包不包含训练数据、标签、论文／资格全文或执行批准；完整私有证据仍独立交接。

## 用法

双方先升级到 0.26 或更新的兼容版本。在各自实际执行研究的 checkout 根目录操作：

```sh
# 发送方：同步冻结已知两类状态，不启动研究
python3 -m research_harness tabular handoff status
python3 -m research_harness tabular handoff export --out /private/path/state.json

# 接收方：只读验证格式，然后明确导入
python3 -m research_harness tabular handoff verify /private/path/state.json
python3 -m research_harness tabular handoff import /private/path/state.json
python3 -m research_harness tabular handoff status

# 原入口也会看到通过统一包导入的约束
python3 -m research_harness tabular memory status
python3 -m research_harness data-blocks status
```

`tabular handoff --root /path/to/checkout ...` 指定状态所在 checkout；默认是当前
安装所在的仓库，不随 shell 工作目录改变。必须导入接收方实际执行所用的 checkout。
`status` 与 `verify` 不创建状态文件、不调用模型、不训练，也不批准实验。
`verify` 只校验格式、摘要及组件内部一致性；不合并本地状态、不做科学审计。

导出会使用现有 checkout 锁读取两类状态的快照。输出不可覆盖，权限 0600。
候选源码、机制、特征指纹、审查者姓名和暂停原因仍可能敏感，分享前须审查。
摘要不是签名或匿名化保证；系统不能认证发送者及其记录真实性。

## 一起生效，不出现半次导入

导入先验证完整包、两个组件和与本地的合并结果。终局冲突、数据重叠、容量超限
或任何组件损坏都会在发布新状态前拒绝。通过后，一个完整包原子发布到：

```text
.research-memory/tabular-state-handoff/<完整包摘要>.json
```

原回归排除读取器和数据暂停读取器都会读取该文件，不再分别写两个生效文件。
发布前中断，两类约束都不新增；发布后回执中断，两类约束都已保留。此时先查看
状态，重复导入同一包会返回 `ALREADY_IMPORTED`，不要删除记录后重试。
临时文件不是已生效状态。原子发布不承诺机器断电后的存储持久性，也不防止有
权限的操作者删除或修改状态库；这仍是可信本地环境中的保守工作流。

只合并新增信息。旧 `RESERVED` 不能覆盖 `STOP/CONTINUE/INVALID`，空包或较旧
快照不能清除暂停／占用；已有科学门槛、停止路线和留出规则不变。损坏、链接、
不兼容版本或名称与摘要不符的已导入包会让两类状态读取拒绝，须核查原记录，
不能通过忽略该包恢复执行。

完整包最多 12 MiB，每个组件最多 4 MiB；合并后也检查组件上限。原有最多
1000 条回归作用域、256 条暂停记录等限制保留。超限需另行设计迁移或扩容，
不能删除消费／暂停记录腾空间。文件系统必须支持同目录硬链接的原子发布；
不支持时明确报错，没有先导入一半的回退路径。

## 与旧命令、私有证据的关系

旧 `tabular memory` 与 `data-blocks` 命令仍可分别导入／导出各自组件，新统一包
加入后这些入口也会看到合并状态。旧组件导入器会拒绝统一包，不能误当成其中
一半。若对方仍使用旧格式，必须继续分别交接两类状态；旧版程序不会认识新增
状态目录，不能用它作为接收后的执行环境。

完整研究记录仍用 `tabular evidence` 单独交接和只读审计。导入统一状态不解包
证据、不恢复旧批准、不自动审核／执行；导入私有证据也不自动导入统一状态。
只有两者都需要时才同时传递，避免把含原始数据和标签的证据包当成普通状态包。

## 覆盖边界

本格式覆盖 Abalone 回归试验的排除记忆，以及 C7 登记的所有数据暂停（暂停可
作用于现有 Abalone/Airfoil 两套基线和候选）。**它不携带 Airfoil 的基线／候选
消费预留，也不携带 SR 记忆或 proposer 启动预留**，因此不是所有研究任务的完整
交接。新数据 adapter、恢复暂停和更多任务记忆需要另行设计并审查。

这是已知状态的离线快照，无法证明发送方已提供所有历史，也没有跨服务器实时锁。
共同数据池仍须先同步、再串行接手；新暂停发生后应再次同步。只读 `status` 在
并发写入期间可能观察到不同时间的组件，不能作为未来执行凭证；正式执行仍在
现有锁内复查当前状态并执行原隔离探针。没有任何新实验授权。
